# shcedule — форум сообщества

Лёгкий форум-сайт, который целиком хостится на **GitHub Pages** (статический
хостинг, бесплатно), а все данные — посты, комментарии и лайки — хранятся в
**GitHub Issues** репозитория. Никакого сервера и базы данных не нужно.

## Возможности

- 📰 **Лента постов** — посты с тегами, поиском и сортировкой (новые / по лайкам / по обсуждениям)
- ✍️ **Посты в Markdown** — редактор с тулбаром и живым предпросмотром
- 💬 **Комментарии** к каждому посту
- 👍 **Лайки** (используются GitHub-реакции `+1`)
- 👤 **Профили** участников и личный вход через GitHub
- 🏷 **Теги** (создаются автоматически как метки GitHub)

## Как это устроено

| Сущность форума | Хранится в GitHub как |
| --- | --- |
| Пост | Issue с меткой `post` |
| Тег | Метка (label) у issue |
| Комментарий | Issue comment |
| Лайк | Реакция `+1` |

Читать форум могут все (без входа). Чтобы писать посты, комментировать и ставить
лайки, участник входит через свой GitHub-аккаунт с помощью персонального токена.

## Запуск локально

Любой статический сервер из папки проекта:

```bash
python3 -m http.server 8000
# открой http://localhost:8000
```

## Деплой на GitHub Pages

1. Запушь эти файлы в ветку (например, `main`).
2. Открой репозиторий → **Settings → Pages**.
3. В разделе **Build and deployment**: Source = *Deploy from a branch*,
   Branch = твоя ветка, папка = `/ (root)`.
4. Сохрани. Через пару минут сайт будет на
   `https://<твой-юзер>.github.io/shcedule/`.

> Совет: добавь в корень пустой файл `.nojekyll` (он уже есть в проекте), чтобы
> GitHub Pages не обрабатывал сайт как Jekyll.

## Вход для участников (личный токен GitHub)

GitHub Pages — статический хостинг, и полноценный OAuth-вход прямо из браузера
GitHub сейчас официально не поддерживает (эндпоинт выдачи токена не отдаёт
CORS-заголовки). Поэтому вход сделан через **fine-grained personal access token** —
это работает без сервера и безопасно, т.к. токен ограничен одним репозиторием.

Как участник входит:

1. Нажимает **Войти** и по подсказке открывает
   `https://github.com/settings/personal-access-tokens/new`.
2. Создаёт **Fine-grained token**:
   - *Repository access* → **Only select repositories** → `shcedule`;
   - *Permissions* → **Issues** → **Read and write**.
3. Вставляет токен в поле входа.

Токен хранится только в `localStorage` браузера участника и отправляется
исключительно на `api.github.com`. Он никогда не попадает на сторонние серверы.

## Настройка

Все настройки — в [`js/config.js`](js/config.js):

- `repo.owner` / `repo.name` — репозиторий, где хранятся посты;
- `site.name` / `site.tagline` — название и слоган форума;
- `postLabel` — метка-маркер поста (по умолчанию `post`);
- `tags` — список тегов (создаются автоматически).

Цвета и шрифты меняются в одном месте — CSS-переменные в начале
[`css/style.css`](css/style.css).

## Структура

```
index.html          каркас страницы
css/style.css       тема (CSS-переменные)
js/config.js        настройки
js/api.js           клиент GitHub API (issues/comments/reactions/labels)
js/auth.js          вход по токену (localStorage)
js/components.js    рендер-хелперы, markdown, иконки
js/app.js           роутер и экраны (лента, пост, композер, профиль)
js/vendor/          marked и DOMPurify (локально, без CDN)
```

## Безопасность

- Весь markdown рендерится через `marked` и очищается через **DOMPurify**
  (защита от XSS), ссылки открываются в новой вкладке с `rel="noopener"`.
- Токен не попадает никуда, кроме `api.github.com`.
