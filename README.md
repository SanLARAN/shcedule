# Форум на GitHub Pages

Полноценный форум (темы, ответы, разделы, теги, лайки, профили, вход через GitHub), который
работает **как статический сайт на GitHub Pages**. Никакого собственного сервера и базы данных:
темы и комментарии хранятся в **GitHub Issues** репозитория, а сайт лишь читает и пишет их
через GitHub API.

```
Браузер ──► GitHub Pages (статика: React + Vite)
                 │
                 └──► GitHub REST API ──► Issues в этом же репозитории
```

* **Темы** = открытые issues
* **Ответы** = комментарии к issue
* **Разделы** = метки/метаданные поста (`Общее`, `Помощь`, `Идеи`, `Проекты`, `Новости`, `Оффтоп`)
* **Лайки** = реакции 👍 на issue
* **Регистрация и вход** = аккаунт GitHub (пароль сайту не передаётся)

## Что уже готово

- Главная с сортировкой (активные / новые / обсуждаемые), фильтром «без ответа» и разделами
- Поиск по темам (GitHub Search API), пагинация «показать ещё»
- Страница темы: Markdown с подсветкой кода, цитатами, таблицами, картинками и предпросмотром
- Ответы прямо с сайта, лайки, закреплённые темы, теги, хлебные крошки
- Страницы «Участники» и профиль автора, страница «О форуме» с правилами
- Тёмная/светлая тема, всплывающие уведомления, скелетоны загрузки, адаптивная вёрстка
- Автосохранение черновика поста в браузере
- **Демо-режим**: сайт работает без GitHub (данные в localStorage) — удобно посмотреть интерфейс
- Если у пользователя нет прав на запись в репозиторий — тема публикуется через форму GitHub,
  а на форуме появляется автоматически
- Кеш ответов API в localStorage (меньше запросов и мгновенные переходы)

## Быстрый старт (локально)

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # прод-сборка в dist/
```

В шапке есть шестерёнка **«Настройки»**: там указываются `owner/repo`, название форума,
`client_id` для входа и переключатель демо-режима. Настройки хранятся в браузере
(localStorage), поэтому одно и то же приложение можно направить на любой репозиторий.

## Публикация на GitHub Pages

1. **Включите Pages через Actions.** Репозиторий → `Settings` → `Pages` → **Source: GitHub Actions**.
2. **Слейте ветку с кодом в `main`.** Workflow `.github/workflows/deploy.yml` сам соберёт проект
   и опубликует его. Сайт появится по адресу `https://<владелец>.github.io/<репозиторий>/`.
3. Первый деплой можно запустить вручную: `Actions` → `Deploy forum to GitHub Pages` → `Run workflow`.

Сборка использует `base: './'`, поэтому сайт корректно работает и в подкаталоге (`/repo/`), и
на собственном домене. В `dist/404.html` копируется `index.html`, чтобы прямые ссылки не 404.

> Если Pages не хочется переключать на Actions: соберите проект и положите содержимое `dist/`
> в каталог `docs/` ветки `main`, затем выберите `Source: Deploy from a branch → main → /docs`.

## Настройка входа через GitHub (рекомендуется)

По умолчанию гость может читать форум, а для публикации попросит войти. Самый удобный способ —
вход по коду (Device Flow), для него нужен только `client_id` OAuth App (секрет не нужен):

1. Откройте <https://github.com/settings/applications/new>
   * *Application name*: `Форум` (любое)
   * *Homepage URL*: `https://<владелец>.github.io/<репозиторий>/`
   * *Authorization callback URL*: тот же адрес (для Device Flow не используется)
2. В созданной OAuth App нажмите **Enable Device Flow** и сохраните.
3. Скопируйте **Client ID** и вставьте его в форуме: значок ⚙️ → поле «GitHub OAuth client_id», затем «Сохранить».
4. Чтобы значение стало общим для всех посетителей, а не только для вашего браузера, впишите его
   в `src/config.ts` → `DEFAULT_CONFIG.clientId` и закоммитьте.

После этого кнопка «Войти» делает всё сама: показывает короткий код, открывает GitHub и ждёт
подтверждения. Альтернатива — вход по personal access token (`public_repo`) прямо из модалки входа.

## Как модерировать

* Темы = issues: их можно закрывать, переоткрывать, помечать метками, закреплять.
* Метка **`pinned`** (или `важное`, `закреплено`) выносит тему в блок «закреплено» наверху главной.
* Раздел темы берётся из метаданных поста: `Общее`, `Помощь`, `Идеи`, `Проекты`, `Новости`, `Оффтоп`.
  В GitHub это метки `cat:general`, `cat:help` и т.д. — их можно проставить вручную, и тема
  переедет в нужный раздел.
* Удаление issue = удаление темы с форума. Закрытая issue отображается с пометкой «закрыто».

## Публикация тем из интерфейса GitHub

В `.github/ISSUE_TEMPLATE/forum-post.yml` лежит форма новой темы: раздел, теги, описание.
Любой пользователь GitHub может открыть issue в публичном репозитории, поэтому это заодно
«внешний» способ публикации, когда у человека нет прав на прямую запись через API.
Парсер понимает оба формата: и нашу форму, и произвольный Markdown.

## Стек

React 18 · TypeScript · Vite 5 · React Router (HashRouter — надёжно работает на GitHub Pages) ·
marked + DOMPurify (безопасный Markdown) · GitHub REST API.

Структура: `src/lib` — доступ к GitHub, модель данных, хранилище (контекст), утилиты;
`src/ui` — компоненты интерфейса и модальные окна; `src/pages` — страницы; `src/styles/app.css` —
единый стилевой слой на CSS-переменных (палитра меняется в одном месте).

## Ограничения

* Запросы к GitHub API без токена ограничены 60 в час — вход увеличивает лимит до 5000.
* Кеш и черновики живут в localStorage, то есть в конкретном браузере.
* Модерация, роли, личные сообщения и уведомления требуют серверной части (Supabase/Firebase) —
  текущая схема сознательно обходится без неё.
